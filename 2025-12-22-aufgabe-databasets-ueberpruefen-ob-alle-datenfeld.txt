● Die Fragezeichen (?) in TypeScript-Interfaces kennzeichnen optionale Eigenschaften.

  Bedeutung der Syntax

  Mit Fragezeichen:
  SumSoll?: number | null;

  Das bedeutet:
  1. Optional: Die Eigenschaft SumSoll muss nicht vorhanden sein
  2. Wenn vorhanden: Kann sie entweder eine Zahl (number) oder null sein

  Ohne Fragezeichen:
  IdNr: number;
  Jahr: number;

  Das bedeutet:
  - Pflichtfeld: Diese Eigenschaften müssen immer vorhanden sein
  - Sie können nicht fehlen

  Praktisches Beispiel

  // ✓ GÜLTIG - alle drei Varianten sind erlaubt:
  const entry1: JournalEntry = {
    IdNr: 1,
    Jahr: 2025,
    Monat: 12,
    BookCircle: "1",
    Kto: 1000,
    GegKto: 2000,
    BelNr: "B001",
    Datum: "2025-12-22",
    Buchungstext: "Test",
    SumSoll: 100,      // Eigenschaft vorhanden mit Wert
    SumHaben: null     // Eigenschaft vorhanden mit null
    // BU fehlt komplett - das ist OK wegen ?
  };

  // ❌ UNGÜLTIG - Pflichtfelder fehlen:
  const entry2: JournalEntry = {
    SumSoll: 100
    // Jahr fehlt → FEHLER, da Jahr kein ? hat!
  };

  Zusammenfassung

  - Mit ? = Optional (kann fehlen)
  - Ohne ? = Pflichtfeld (muss vorhanden sein)
  - | null = Wenn vorhanden, kann der Wert auch null sein

  In Ihrem JournalEntry Interface sind also nur die ersten 9 Felder (IdNr bis Buchungstext) Pflichtfelder, alle anderen mit ? sind optional.

● Erklärung der roten Wellenlinie

  Der TypeScript-Fehler:

  Was passiert in Zeile 7-9:

  const yearParam = url.searchParams.get('year');
  const monthParam = url.searchParams.get('month');
  const bookCircleParam = url.searchParams.get('bookCircle');

  Typ dieser Variablen: string | null

  (Die Methode searchParams.get() gibt entweder einen String ODER null zurück, wenn der Parameter nicht existiert)

  ---
  Was erwartet fetchPrimanota (Zeile 110-118):

  export interface PrimanotaParams {
    year?: number | string;
    month?: number | string | 'All';
    bookCircle?: number | string;
    // ...
  }

  Erlaubte Typen:
  - year: number | string | undefined
  - month: number | string | 'All' | undefined
  - bookCircle: number | string | undefined

  ---
  Der Typ-Konflikt

  // Zeile 11-13:
  const result = fetchPrimanota({
    year: yearParam,        // ❌ Typ ist string | null
    month: monthParam,      // ❌ Typ ist string | null  
    bookCircle: bookCircleParam  // ❌ Typ ist string | null
  });

  Problem:
  - Übergeben wird: string | null
  - Erwartet wird: number | string | undefined

  TypeScript-Regel:
  - null ≠ undefined
  - Das ? in year?: number | string bedeutet: "optionaler Parameter" → Typ ist number | string | undefined
  - null ist NICHT in dieser Typ-Definition enthalten

  ---
  Zusammenfassung

  Die rote Wellenlinie erscheint, weil:

  1. url.searchParams.get() → gibt string | null zurück
  2. PrimanotaParams.year → erwartet number | string | undefined
  3. null ist nicht kompatibel mit number | string | undefined

  TypeScript meldet: "Type 'string | null' is not assignable to type 'number | string | undefined'"
