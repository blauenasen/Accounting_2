## 📝 WICHTIGE HINWEISE FÜR NÄCHSTE SESSION

### 1. Design-System-Quelle
- **Datei:** `ACCOUNTING_DESIGN_SYSTEM.md`
- Alle CSS-Variablen stammen aus diesem Dokument
- Bei Unsicherheiten: Diese Datei ist die Single Source of Truth

### 2. Layout-Strategie
- **Absolute Positioning** wird im Original verwendet
- Fixed Top-Offsets: Header (50px), Inputs (100px), Buttons (165px/225px), Tables (225px/265px)
- Nicht responsive - Desktop-First-Ansatz

### 3. Modulare CSS-Struktur
```
src/lib/styles/
├── variables.css          # CSS Custom Properties (Design Tokens)
├── global.css             # Base Styles, Page Layout
├── components/
│   ├── buttons.css        # Button-System
│   ├── forms.css          # Form Components
│   └── tables.css         # Table Components
└── pages/
    ├── rates.css          # Rates-Page-Specific
    ├── debtors.css        # Debtors-Page-Specific
    ├── creditors.css      # Creditors-Page-Specific
    └── booking.css        # Booking-Page-Specific
```

### 4. Import-Reihenfolge in +layout.svelte
```svelte
import '$lib/styles/variables.css';   // 1. Variablen zuerst
import '$lib/styles/global.css';      // 2. Global Styles
import '$lib/styles/components/buttons.css';
import '$lib/styles/components/forms.css';
import '$lib/styles/components/tables.css';
// Page-specific CSS wird in den jeweiligen +page.svelte importiert
```

### 5. 500-Zeilen-Regel
- Alle CSS-Dateien halten sich daran
- Größte Datei: forms.css mit 215 Zeilen
- Bei Komponenten-Styling aufpassen!

### 6. Git-Workflow
- Feature-Commits nach jeder abgeschlossenen Phase
- Message-Format: `feat: Implement Phase X.Y - [Description]`

## 💡 LESSONS LEARNED

1. **CSS-Variablen sind Gold wert** - Konsistenz überall, einfache Änderungen

4. **Absolute Positioning funktioniert** - Wenn Dimensionen bekannt sind (Desktop-App)
